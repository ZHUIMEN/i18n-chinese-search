**结论先行：`TextEditorDecorationType.after.contentText` 画出来的中文是**纯渲染层虚拟文本**，不可能被 VS Code 的全局搜索（Ctrl+Shift+F）索引到。** 搜索只针对磁盘/内存中的文档文本，decoration 不影响 `document.getText()` 的结果。

想让「中文 → 代码」一步完成，**唯一可行的方向是：自己写一个自定义搜索命令**，内部自动完成「中文 → key → 全局搜索」的链路。

---

### 推荐方案：扩展提供一个 `i18n: 中文定位代码` 命令

实现思路：扩展读取语言包建立 `Map<中文, key[]>`，用户输入中文后，自动找到 key，再调用 VS Code 原生的 `findInFiles` 打开搜索结果。

#### 核心代码示例

```typescript
import * as vscode from 'vscode';
import * as fs from 'fs';
import * as path from 'path';

// 1. 拍平语言包，建立 中文 -> key数组 的反向索引
async function buildReverseMap(workspaceRoot: string): Promise<Map<string, string[]>> {
    const map = new Map<string, string[]>();
    // 根据你的项目结构调整路径
    const localePath = path.join(workspaceRoot, 'src', 'locales', 'zh-CN.json');
    
    if (!fs.existsSync(localePath)) return map;
    
    const content = JSON.parse(fs.readFileSync(localePath, 'utf-8'));
    
    const walk = (obj: any, prefix = '') => {
        for (const [k, v] of Object.entries(obj)) {
            const key = prefix ? `${prefix}.${k}` : k;
            if (typeof v === 'string') {
                const arr = map.get(v) || [];
                arr.push(key);
                map.set(v, arr);
            } else if (v && typeof v === 'object') {
                walk(v, key);
            }
        }
    };
    walk(content);
    return map;
}

// 2. 注册命令：输入中文，自动跳转全局搜索
export function activate(context: vscode.ExtensionContext) {
    const disposable = vscode.commands.registerCommand('i18n.searchByChinese', async () => {
        const input = await vscode.window.showInputBox({
            placeHolder: '输入要搜索的中文，如：用户名',
            prompt: 'i18n 中文反向定位'
        });
        if (!input) return;

        const wf = vscode.workspace.workspaceFolders?.[0];
        if (!wf) return;

        const map = await buildReverseMap(wf.uri.fsPath);
        const keys = map.get(input);

        if (!keys || keys.length === 0) {
            vscode.window.showWarningMessage(`未找到中文 "${input}" 对应的 i18n key`);
            return;
        }

        // 构建正则：匹配 'key'、"key"、`key`
        const escaped = keys.map(k => k.replace(/\./g, '\\.')).join('|');
        const query = `['"\`](${escaped})['"\`]`;

        // 3. 直接打开 VS Code 全局搜索面板并填入正则
        await vscode.commands.executeCommand('workbench.action.findInFiles', {
            query: query,
            isRegex: true,
            triggerSearch: true,
            matchCase: false,
            matchWholeWord: false
        });
    });

    context.subscriptions.push(disposable);
}
```

### 为什么其他方案行不通

| 方案 | 问题 |
|:---|:---|
| **Decoration / InlayHint / CodeLens** | 全部是渲染层虚拟文本，不进入文档模型，任何搜索都索引不到 |
| **直接修改源码写入中文注释** | 可以搜到，但污染代码，且需要构建时删除 |
| **Language Server 拦截搜索** | VS Code 没有开放让扩展拦截或扩展 `Ctrl+Shift+F` 文本索引的 API |
| **`registerTextSearchProvider`** | 该 API 是给远程文件系统（如 SSH、虚拟工作区）提供文件内容用的，不是给已有文档加虚拟文本用的 |

### 进阶优化（可选）

- **缓存语言包**：用 `fs.watch` 或 `vscode.workspace.createFileSystemWatcher` 监听 `zh-CN.json` 变更，避免每次搜索都重新解析
- **模糊搜索**：不用 `Map.get()`，而是用 `fuse.js` 做中文模糊匹配，支持输入部分文字
- **多语言文件**：如果语言包分散在多个文件，遍历 `locales` 目录合并
- **结果直接跳转**：不调用 `findInFiles`，而是用 `vscode.workspace.findFiles` + 读取文件内容自己匹配，然后用 `vscode.Location` 在 Peek 窗口或自定义 TreeView 中展示，体验更紧凑

**一句话总结：虚拟文本进不了搜索索引，不要死磕 Decoration；写一个自定义命令接管搜索逻辑，是工程上最干净、最可控的做法。**
